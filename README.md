## Overview

**GitHub Achievement Hunt** is a small, static website for exploring six GitHub profile achievement names and the activity commonly associated with them. Each card opens an on-site guide with a description, caveats about requirements and availability, responsible next steps, and links to relevant GitHub documentation.

The project is intentionally lightweight: it uses browser-native technologies and needs no build step, package installation, account, backend, or Firebase setup.

## Features

- Browse six achievement cards with the original badge artwork stored in the repository.
- Search achievement names, descriptions, categories, and related terms.
- Filter by category or profile status, and sort by guide order, name, or category.
- Open an accessible in-page details dialog from a card; close it with its button, the Escape key, or the backdrop.
- Use the Explorer on desktop or mobile, with keyboard navigation and reduced-motion support.
- Read cautious, badge-specific guides without fabricated thresholds or claims of verified awards.

> Profile status is **unknown** for this static guide. Search, filtering, and the details panel never check or change a GitHub account.

### Badge-specific guidance

These notes summarize the in-site guides. They are responsible contribution suggestions—not award criteria or guarantees.

<details>
<summary><strong>Quickdraw</strong></summary>

GitHub has not confirmed the often-repeated timing rule or a current eligibility threshold in the public documentation linked here. Work on genuine issues or pull requests, and resolve or close them only when the work and project process call for it. Do not race a timer or create activity to pursue a badge.

</details>

<details>
<summary><strong>Pull Shark</strong></summary>

The badge is commonly associated with merged pull requests, but GitHub does not publish a qualifying count or guarantee an award. Choose a useful contribution, follow the repository's review and testing process, and let maintainers decide whether to merge it.

</details>

<details>
<summary><strong>YOLO</strong></summary>

The commonly repeated no-review description is not a published award rule. Follow repository policy, required reviews, branch protections, and checks. Never skip or disable a safeguard to pursue an achievement.

</details>

<details>
<summary><strong>Galaxy Brain</strong></summary>

The badge is commonly associated with answers accepted in GitHub Discussions, but no public award count is specified. Offer a clear, accurate answer where it can help; the discussion author or a maintainer decides whether it resolves the question.

</details>

<details>
<summary><strong>Starstruck</strong></summary>

The badge is commonly associated with stars received by a repository. Thresholds and ownership rules are not specified in the linked public documentation. Build and maintain something useful; other people decide independently whether to star it.

</details>

<details>
<summary><strong>Pair Extraordinaire</strong></summary>

The badge is commonly associated with genuine co-authored contributions, but its precise criteria are not publicly specified. Credit collaborators accurately and only for work they actually contributed.

</details>

### Historical and separate profile badges

The **Arctic Code Vault Contributor** badge is associated with GitHub's one-time public-repository snapshot on February 2, 2020. The [GitHub Archive Program](https://archiveprogram.github.com/) documents that historical snapshot; it does not establish a current route to earn a badge. **Mars 2020 Contributor** is also a legacy badge name; the official references reviewed do not establish current eligibility.

These historical badges are not among the six Explorer cards. GitHub's [profile reference](https://docs.github.com/en/account-and-profile/reference/profile-reference) also distinguishes program or account badges—such as Developer Program Member, Pro, Security Bug Bounty Hunter, and GitHub Campus Expert—from activity achievements. These are separate from this project's badge guide.

## Get started

### Requirements

- A modern web browser.
- Python 3 if you want to run a local static file server.
- Node.js if you want to run the automated tests.

There is no dependency installation or production build step.

### Run locally

Clone the repository and enter its directory:

```bash
git clone https://github.com/rahulde2007/Github-Achievement-Hunt.git
cd Github-Achievement-Hunt
```

Start **one** static server from the repository root:

```bash
# Python 3
python3 -m http.server 8000
```

On Windows, the Python launcher can be used instead:

```powershell
py -m http.server 8000
```

With Python's server running, open <http://localhost:8000> in your browser. You can also use an editor's static-site preview server.

### Run the tests

From the repository root, run:

```bash
node --test
```

The tests cover the six local badge assets, Explorer search/filter/sort behavior, and the completeness and safety of the achievement guides.

## Use the Explorer

1. Open an achievement card—or its **View instructions** button—to read its in-site guide.
2. Search by name, category, description, or related activity.
3. Narrow the list with the category and profile-status filters.
4. Choose guide order, alphabetical name order, or category order.
5. Use **Reset search and filters** to return to the full guide.

The details panel describes general activity and uncertainty; it cannot determine whether a visitor qualifies for or has received an achievement.
